# Технические исследования и решения

## Исследованные технологии

### NestJS Framework

**Версия**: 10.3.0  
**Источник**: https://nestjs.com/

**Решение**: Использован NestJS как основной framework по следующим причинам:
- Модульная архитектура с DI контейнером
- Отличная поддержка TypeScript из коробки
- Встроенная поддержка Express/Fastify
- Простая интеграция middleware и interceptors
- Активное сообщество и документация

**Альтернативы рассмотренные**:
- Fastify - быстрее, но менее зрелый экосистема
- Express напрямую - больше boilerplate кода

### Microsoft SQL Server Driver (mssql)

**Версия**: 12.2.0  
**Источник**: https://github.com/tediousjs/node-mssql

**Важные изменения в версии 12.x**:
- Параметр `encrypt` теперь должен быть `boolean` или `"strict"`, не может быть `undefined`
- Улучшенная поддержка TypeScript
- Новый API для connection pooling

**Решение**: Используем версию 12.2.0 с правильной обработкой параметра encrypt:
```typescript
let encrypt: boolean | 'strict' = false;
if (encryptValue === 'true') {
  encrypt = true;
} else if (encryptValue === 'strict') {
  encrypt = 'strict';
}
```

### OData Protocol

**Версия**: 4.0  
**Спецификация**: https://www.odata.org/documentation/

**Ключевые требования**:
- Metadata в формате EDMX (XML), не JSON
- Content-Type для metadata: `application/xml`
- Content-Type для данных: `application/json; odata.metadata=minimal`
- Заголовок `OData-Version: 4.0`
- Поле `@odata.context` в JSON ответах

**Excel требования**:
- Excel запрашивает метаданные по пути `/$metadata` (без префикса `/api`)
- Excel ожидает XML формат метаданных (EDMX)
- Excel проверяет наличие `@odata.context` в ответах

### TypeScript

**Версия**: 5.3.3  
**Конфигурация**: Строгий режим отключен для совместимости с NestJS и быстрой разработки

**Особенности конфигурации**:
```json
{
  "strictNullChecks": false,
  "noImplicitAny": false,
  "strictBindCallApply": false

```

## Архитектурные решения

### Connection Pooling

**Решение**: Использование встроенного connection pool из mssql драйвера

**Параметры пула**:
- `max: 10` - максимум соединений
- `min: 0` - минимум соединений (создаются по требованию)
- `idleTimeoutMillis: 30000` - timeout для неактивных соединений

**Преимущества**:
- Автоматическое управление соединениями
- Переиспользование соединений
- Защита от превышения лимитов сервера

### Безопасность SQL запросов

**Проблема**: Необходимо защититься от SQL инъекций

**Решение трех уровней**:

1. **Валидация имен таблиц**:
   - Regex: `/^[a-zA-Z_][a-zA-Z0-9_]*$/`
   - Блокирует специальные символы SQL

2. **Параметризованные запросы**:
   - Все значения передаются через `request.input(key, value)`
   - Драйвер автоматически экранирует значения

3. **Экранирование имен полей**:
   - Все имена оборачиваются в квадратные скобки: `[columnName]`
   - Защищает от конфликтов с ключевыми словами SQL

### Обработка метаданных

**Проблема**: Генерация EDMX XML для Excel и других клиентов

**Решение**:
- Динамическое обнаружение схемы через `INFORMATION_SCHEMA`
- Преобразование SQL типов в OData Edm типы
- Генерация XML вручную (без XML библиотек для простоты)
- Экранирование XML специальных символов

### Логирование

**Требования**: Детальное логирование для отладки

**Решение**: Собственный middleware вместо сторонних библиотек

**Причины**:
- Полный контроль над форматом логов
- Нет дополнительных зависимостей
- Простота кастомизации
- Уникальный ID запроса для трассировки

**Особенности реализации**:
- Использование замыканий для сохранения контекста `this`
- Безопасная сериализация с обработкой циклических ссылок
- Форматирование размера ответа в человекочитаемый вид

### CORS и OPTIONS

**Проблема**: Excel и веб-клиенты требуют CORS поддержку

**Решение**: 
- Глобальное включение CORS через `app.enableCors()`
- Специальный обработчик `@Options('*')` для всех путей
- Правильные заголовки для OData: `OData-Version`, `OData-MaxVersion`

## Известные ограничения

### Первичные ключи

**Текущее поведение**: Первая колонка используется как ключ

**Ограничение**: Не учитываются составные ключи или ключи, которые не являются первой колонкой

**Решение для будущего**: Запрос к `INFORMATION_SCHEMA.KEY_COLUMN_USAGE` для определения реальных ключей

### Views

**Текущее поведение**: Поддерживаются только таблицы типа `BASE TABLE`

**Ограничение**: Views из `INFORMATION_SCHEMA.VIEWS` не включаются

**Решение для будущего**: Добавить опцию включения views через конфигурацию

### Производительность метаданных

**Текущее поведение**: Метаданные генерируются при каждом запросе

**Ограничение**: Для баз с большим количеством таблиц это может быть медленно

**Решение для будущего**: Кэширование метаданных с TTL и инвалидацией при изменении схемы

## Интеграция с клиентами

### Excel

**Требования**:
- Metadata endpoint по пути `/$metadata` (без `/api`)
- XML формат метаданных (EDMX)
- Правильные OData заголовки

**Решение**: Создан отдельный RootController для обработки корневых путей

### Power BI

**Требования**: Аналогичны Excel, но более строгие к формату метаданных

**Статус**: Должен работать, но не протестировано

### Postman / HTTP клиенты

**Требования**: Стандартный REST API

**Статус**: Полностью поддерживается

## Производительность

### SQL запросы

- Использование `OFFSET ... FETCH NEXT` для пагинации (эффективнее чем TOP в подзапросах)
- Connection pooling для переиспользования соединений
- Параметризованные запросы для кэширования планов выполнения

### Логирование

- Логирование в production можно отключить через переменную окружения
- Размер логируемых данных ограничен (500 символов для preview)
- Асинхронная обработка логирования не блокирует основной поток

## Безопасность

### SQL Injection

- ✅ Валидация имен таблиц
- ✅ Параметризованные запросы
- ✅ Экранирование имен полей

### XSS

- Не применимо (нет HTML вывода)

### CORS

- Настроен на `origin: '*'` (можно ограничить через конфигурацию)
- Поддержка preflight запросов

### Rate Limiting

- ❌ Не реализовано
- 📋 Запланировано для будущих версий
