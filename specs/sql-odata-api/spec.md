# SQL OData REST API - Спецификация

## Обзор

SQL OData REST API - это RESTful веб-сервис, предоставляющий доступ к данным Microsoft SQL Server через протокол OData 4.0. Приложение построено на NestJS и обеспечивает полную поддержку стандартных OData операций с динамическим обнаружением схемы базы данных.

## Цели проекта

- Предоставить REST API для доступа к любым таблицам MS SQL Server
- Реализовать полную поддержку OData 4.0 протокола
- Обеспечить безопасность через параметризованные SQL запросы
- Поддержать интеграцию с клиентами OData (Excel, Power BI, и др.)
- Предоставить детальное логирование для отладки

## Пользовательские истории

### US-1: Получение метаданных базы данных
**Как** администратор базы данных  
**Я хочу** получить список всех доступных таблиц и их структуру в формате OData EDMX  
**Чтобы** клиенты OData могли автоматически определить доступные entity sets

**Критерии приемки:**
- Endpoint `GET /$metadata` возвращает XML в формате EDMX 4.0
- Метаданные включают все таблицы из всех схем (кроме системных)
- Каждая таблица описана как EntityType с полным списком свойств
- Типы данных правильно преобразованы из SQL в OData Edm типы

### US-2: Получение коллекции записей с фильтрацией
**Как** клиент приложения  
**Я хочу** получать данные из таблиц с поддержкой фильтрации, сортировки и пагинации  
**Чтобы** эффективно работать с большими объемами данных

**Критерии приемки:**
- Поддержка параметра `$filter` с операторами OData (eq, ne, gt, ge, lt, le, and, or, not)
- Поддержка строковых функций (contains, startswith, endswith)
- Поддержка параметра `$orderby` для сортировки
- Поддержка `$top` и `$skip` для пагинации
- Поддержка `$select` для выбора конкретных полей
- Поддержка `$count` для получения общего количества записей

### US-3: CRUD операции над записями
**Как** клиент приложения  
**Я хочу** создавать, читать, обновлять и удалять записи в таблицах  
**Чтобы** управлять данными через REST API

**Критерии приемки:**
- `GET /api/{table}` - получение коллекции записей
- `GET /api/{table}({key})` - получение одной записи по ключу
- `POST /api/{table}` - создание новой записи
- `PUT /api/{table}({key})` - полное обновление записи
- `PATCH /api/{table}({key})` - частичное обновление записи
- `DELETE /api/{table}({key})` - удаление записи

### US-4: Поддержка CORS и OPTIONS запросов
**Как** веб-приложение  
**Я хочу** делать запросы из браузера с другого домена  
**Чтобы** интегрировать API в веб-приложения

**Критерии приемки:**
- Поддержка CORS заголовков
- Обработка OPTIONS запросов
- Правильные заголовки для OData клиентов

### US-5: Детальное логирование
**Как** разработчик  
**Я хочу** видеть детальные логи всех запросов и ответов  
**Чтобы** отлаживать проблемы и оптимизировать производительность

**Критерии приемки:**
- Логирование всех HTTP запросов с параметрами
- Логирование SQL запросов перед выполнением
- Логирование времени выполнения запросов
- Логирование размера ответов
- Уникальный ID для каждого запроса для трассировки

## Технические требования

### Технологический стек
- **Framework**: NestJS 10.x
- **Language**: TypeScript 5.x
- **Database**: Microsoft SQL Server (через mssql драйвер 12.x)
- **Runtime**: Node.js 20.x
- **HTTP Server**: Express (через @nestjs/platform-express)

### Зависимости
- @nestjs/common, @nestjs/core, @nestjs/config
- mssql (Microsoft SQL Server драйвер)
- class-validator, class-transformer (валидация)
- reflect-metadata, rxjs

### Безопасность
- Валидация имен таблиц (защита от SQL инъекций через имена)
- Параметризованные SQL запросы для всех значений
- Валидация входных данных через ValidationPipe
- CORS настраивается глобально

### Производительность
- Connection pooling для SQL Server
- Асинхронная обработка всех запросов
- Эффективная обработка больших результатов через пагинацию

## API Endpoints

### Service Root
- `GET /` - корневой endpoint сервиса
- `GET /api` - корневой endpoint API с информацией о доступных ресурсах

### Metadata
- `GET /$metadata` - XML метаданные в формате EDMX 4.0
- `GET /api/$metadata` - альтернативный путь к метаданным

### Entity Sets
- `GET /api/{table}` - получение коллекции записей
- `GET /api/{table}({key})` - получение одной записи
- `POST /api/{table}` - создание записи
- `PUT /api/{table}({key})` - полное обновление записи
- `PATCH /api/{table}({key})` - частичное обновление записи
- `DELETE /api/{table}({key})` - удаление записи

## OData Query Parameters

- `$filter` - фильтрация записей
- `$orderby` - сортировка
- `$top` - ограничение количества записей
- `$skip` - пропуск записей
- `$select` - выбор полей
- `$count` - включение счетчика записей

## Ограничения

- Первая колонка таблицы используется как первичный ключ
- Имена таблиц должны соответствовать regex: `/^[a-zA-Z_][a-zA-Z0-9_]*$/`
- Только таблицы типа BASE TABLE (не views, не системные таблицы)
- Максимальный размер пула соединений: 10

## Обработка ошибок

- 400 Bad Request - невалидное имя таблицы или параметры
- 404 Not Found - таблица не найдена или запись не найдена
- 500 Internal Server Error - ошибка базы данных или сервера

Все ошибки возвращаются в формате JSON с полями:
- `message` - описание ошибки
- `error` - тип ошибки
- `statusCode` - HTTP статус код
